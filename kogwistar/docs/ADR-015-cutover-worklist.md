# ADR-015 Cutover Worklist

**Scope:** Execution tasklets for the still-open gates in [ADR-015 implementation status](ADR-015-implementation-status.md). Adds no requirements; expands only its unchecked rollout gates.
**Progress:** **0/63 PASS (0%)**. Counts production/deployment work only; not code completion or overall Rust migration percentage.
**Baseline:** ADR-015 reports 2/8 Rust-target capabilities locally ready, 6/8 not ready, and 0/40 production canary stage observations. This worklist tracks the remaining production gates. Each promotion requires its own evidence; no capability inherits another's result.
**Excludes:** ADR-022 evidence inventory (911/911 fine tasklets pass), completed NSV worklist (5/5), and Python-owned Chroma adapter.

## Counting Rules

- Fixed denominator: 63 leaves = 40 capability-stage observations + 8 rollback drills + 8 per-capability promotion decisions + 7 final rollout/release gates.
- The five stages are the ADR-defined `internal/test`, `1%`, `10%`, `50%`, and `100%`; each row is one independently promotable decision for one capability.
- Status changes require current candidate identity, dated evidence, and a link to the actual run/report. A local test or rehearsal never counts as a production stage.
- Keep Python selectable and rollback-safe. Never promote an unready capability, infer evidence from another capability, or change the denominator without an approved ADR scope change.
- Production target, operator, and observation windows require maintainer authorization; NOT STARTED means not yet executed, not a code defect.
